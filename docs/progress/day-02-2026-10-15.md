## 1. Objective

💡 **In plain words:** an IP address is the **address of a building** (which machine). A **port** is a **door number** inside that building (which program). Every service waits behind its own numbered door: SSH behind door 22, DNS behind door 53, a website behind door 80. Before opening new doors, I made an inventory of which doors app01 already has open – and to whom.

🔧 **Technical:** list all listening TCP and UDP sockets on app01 with the owning process, and interpret the result.

## 2. Procedure

```bash
sudo ss -tulpn   # ss = socket statistics
#  -t  TCP sockets        -u  UDP sockets
#  -l  only listening      -p  show the owning process
#  -n  numbers, not names  (memory aid: "tulpn" = tulip)
```

## 3. Reading the output

| Column | Technical meaning | In plain words | In my output |
|---|---|---|---|
| **Netid** | Protocol: TCP or UDP | TCP = a phone call (confirmed); UDP = a postcard (just sent) | `udp` and `tcp` |
| **State** | LISTEN = TCP socket waiting for connections; UNCONN = open UDP socket (UDP never connects); ESTAB = an active TCP connection | LISTEN = a door open and waiting; UNCONN = a letterbox ready for letters | `UNCONN` (udp), `LISTEN` (tcp) |
| **Recv-Q** | Bytes received but not yet read by the program | Letters that arrived but are not opened yet | `0` – nothing waiting |
| **Send-Q** | On a LISTEN socket: the maximum queue of waiting connections | How many visitors may queue at the door | `4096` on the DNS helper's TCP socket; `0` for UDP (no queue) |
| **Local Address:Port** | IP and port on this machine where the socket listens | Building address + door number | `127.0.0.53%lo:53` |
| **Peer Address:Port** | The other end of a connection | Who is visiting | `0.0.0.0:*` – nobody yet, anyone may come |
| **Process** | Program name, process ID, file descriptor | Which program sits behind the door | `systemd-resolve`, pid 842, fd 13 (UDP) and fd 14 (TCP) |

**The address in detail:** `127.0.0.53 % lo : 53` = the loopback address (127.x = the machine talking to itself), bound to the loopback card `lo`, on port 53 (DNS). Reachable **only from programs inside app01**.

**fd (file descriptor):** the number a program uses for something it has open – in Linux almost everything is a file, including network sockets. fd 13 and fd 14 are the DNS helper's two sockets.

## 4. TCP and UDP – the background

| | TCP | UDP |
|---|---|---|
| Start | **3-way handshake:** SYN → SYN-ACK → ACK ("Can you hear me?" – "Yes, can you hear me?" – "Yes") | No handshake – it just sends |
| Lost data | Noticed and re-sent automatically – reliable | Lost for good – no check |
| Speed | Slower, but sure | Faster, no guarantee |
| In `ss` | LISTEN → ESTAB | UNCONN |
| Used for | SSH (22), websites (80/443) | DNS (53), video calls, games |

DNS uses UDP for short questions and TCP for answers too large for one packet – that is why the DNS helper listens on both. The firewall rule `ESTABLISHED,RELATED` from Step 1.3 means exactly "packets belonging to a TCP conversation that already completed its handshake".

## 6. Key understanding (in my own words)

> **Netid** is the protocol, TCP or UDP. **TCP** starts every conversation with a 3-way handshake (SYN, SYN-ACK, ACK); after that the connection is **ESTAB**. **UDP** has no handshake – it just sends.
>
> **Every port leads directly to its own program.** The port number decides which program receives the traffic: port **22** → **sshd** (SSH), port **53** → the **DNS helper**, port **80** → a web server. Traffic does **not** pass through the DNS helper first. A port with no program behind it is closed – nobody answers.
>
> **LISTEN** = a TCP door is open and waiting. **UNCONN** = a UDP door is open.
> **Recv-Q** = data received but not read yet (0 = nothing waiting). **Send-Q** on a LISTEN socket = how many visitors may wait in the queue (4096 for the DNS helper's TCP socket).
> **Local address** = this machine's address and door, e.g. `127.0.0.53%lo:53` = the DNS helper on the loopback card, port 53, reachable only from inside app01. **Peer address** = who is visiting – `0.0.0.0:*` = nobody yet; in a real connection it shows the visitor's IP and its random port, e.g. `192.168.60.1:51234` = gw01.
>
> **A port is a door number; a socket is a program standing at that door on a specific machine (IP + port + protocol); a connection is two sockets talking to each other.**
>
> **DNS has one job: translate a name into an IP address** – the phone book, not the phone line. Lookup order on app01: **`/etc/hosts`** (own contact list) → **local DNS helper** `127.0.0.53` (answers from its cache) → **outside DNS server** `1.1.1.1` / `8.8.8.8` through gw01. Once the IP is known, the real traffic goes directly to that IP and port. In a company, an **internal DNS server** answers internal names; in our lab `/etc/hosts` does that job.
>
> **On app01 right now** the only open port is 53, used by the local DNS helper, and only from inside app01. app01 accepts **no connections from the network**. Next: install SSH so port 22 opens.
